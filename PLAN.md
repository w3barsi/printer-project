# Rename the Public App to Storefront

## Goal

Rename the customer-facing application from `public` to `storefront` everywhere that `public` identifies the application, without changing its URLs, routes, behavior, or legitimate access-level terminology.

Final application identity:

- Workspace directory: `apps/storefront`
- Package name: `@dg/storefront`
- Root scripts: `build:storefront` and `deploy:storefront`
- Cloudflare Worker: `darcygraphix-storefront`
- Production domain: `https://darcygraphix.com` (unchanged)
- Development port: `3000` (unchanged)

## Naming Boundary

Only rename `public` when it means the customer-facing application.

Keep these uses of `public` unchanged:

- `apps/storefront/public/`, because `public` is the conventional static-asset directory.
- `publicDir: "public"` in Vite configuration.
- Public Drive sharing names such as `PublicShareBrowser`, `PublicShareItem`, `publicAccess`, `publicToken`, `publicSafe`, and user-facing text such as "Public link".
- Convex terminology for public functions and public APIs.
- TypeScript, Web API, cryptography, and generated-code uses of `public`.
- Generated `routeTree.gen.ts` content; do not edit this file manually.

## Execution Plan

### 1. Establish a Clean Rename Baseline

1. Read `AGENTS.md` and follow all repository restrictions.
2. Run `git status --short` and note existing user changes. Do not revert or overwrite unrelated work.
3. Search tracked source and configuration for the app identity:

   ```sh
   rg -n 'apps/public|@dg/public|build:public|deploy:public|darcygraphix-public|publicAppOrigin|PUBLIC_ORIGIN|PublicRouterContext|backend,public,system' \
     --glob '!**/node_modules/**' \
     --glob '!**/dist/**' \
     --glob '!**/.output/**'
   ```

4. Record any additional CI, deployment, editor, or documentation references not listed below and include them in the same rename.

### 2. Rename the Workspace Directory

1. Remove or leave behind only ignored build caches that should not be carried into the renamed workspace, including `dist/`, `.output/`, `.nitro/`, `.wrangler/`, and generated `worker-configuration.d.ts`. Do not remove the tracked `public/` static-asset directory.
2. Rename `apps/public` to `apps/storefront` as a Git-aware move so history remains visible.
3. Confirm all tracked source files now appear under `apps/storefront`, including `apps/storefront/public/`.
4. Do not manually edit `apps/storefront/src/routeTree.gen.ts`.

### 3. Rename the Workspace and Root Commands

1. In `apps/storefront/package.json`, change the package name from `@dg/public` to `@dg/storefront`.
2. In the root `package.json`:
   - Change the concurrent process label from `public` to `storefront`.
   - Change the filter from `@dg/public` to `@dg/storefront`.
   - Rename `build:public` to `build:storefront`.
   - Make the root `build` script call `build:storefront`.
   - Rename `deploy:public` to `deploy:storefront`.
   - Update `cf:typegen` to filter `@dg/storefront`.
3. Do not add compatibility aliases for the old package or script names; this is an internal monorepo rename with no identified external consumers.
4. Run `pnpm install --lockfile-only` from the workspace root so the lockfile importer changes from `apps/public` to `apps/storefront` through pnpm rather than by hand.
5. Verify that `pnpm-lock.yaml` has an `apps/storefront` importer and no `apps/public` importer.

### 4. Rename App-Specific Code Symbols

1. In `apps/storefront/src/routes/__root.tsx`, rename `PublicRouterContext` to `StorefrontRouterContext`.
2. In `apps/system/src/lib/app-origins.ts`, rename `publicAppOrigin` to `storefrontOrigin`.
3. Update the corresponding import and share-link construction in `apps/system/src/components/drive/share-dialog.tsx`.
4. Keep the production origin `https://darcygraphix.com` and development origin `http://localhost:3000` unchanged.
5. Do not rename public-share components, types, fields, routes, or UI language. They describe unauthenticated sharing, not the storefront application.

### 5. Rename the Legacy Redirect Binding

1. In `workers/cfsystem-redirect/src/index.ts`, rename the app-specific environment binding from `PUBLIC_ORIGIN` to `STOREFRONT_ORIGIN`.
2. Update the redirect selection to read `env.STOREFRONT_ORIGIN`.
3. In `workers/cfsystem-redirect/wrangler.jsonc`, rename the variable key to `STOREFRONT_ORIGIN` while keeping its value `https://darcygraphix.com`.
4. Do not change redirect paths, status codes, domains, or routing behavior.

### 6. Rename the Cloudflare Worker Identity

1. In `apps/storefront/wrangler.jsonc`, change `darcygraphix-public` to `darcygraphix-storefront`.
2. Keep the custom domain pattern `darcygraphix.com` unchanged.
3. Treat this as a production resource cutover, not only a source rename: a new Worker name can create a new Cloudflare Worker while the old Worker still exists.
4. Do not deploy during implementation or verification without explicit approval for the production-affecting action.

### 7. Update Repository Terminology and Documentation

1. In `AGENTS.md`:
   - Replace the glossary definition for `public` with `storefront`, defined as the customer-facing web app.
   - Change `apps/public` to `apps/storefront`.
   - Preserve the separate Convex rule where "Public" means `query`, `mutation`, or `action`.
2. In `README.md`:
   - Label the customer-facing surface as `Storefront`.
   - Change `apps/public` to `apps/storefront` and `@dg/public` to `@dg/storefront`.
   - Replace the old build, deploy, and filter command examples.
   - Change the Worker name to `darcygraphix-storefront`.
   - Keep descriptions of public Drive shares and the public domain accurate where `public` describes access.
3. Review `docs/monorepo-preflight.md` and change terms such as "public site" or "public area" to "storefront" only when they identify this app. Preserve paths such as `public/robots.txt` and concepts such as public shares.
4. Update any additional current documentation, CI, or operational configuration found in step 1.

### 8. Regenerate Derived Local Artifacts

1. Run the repository's Cloudflare type generation command after all filters and directories are renamed:

   ```sh
   pnpm cf:typegen
   ```

2. Generated `worker-configuration.d.ts` files are ignored; use this step only to confirm Wrangler resolves both renamed workspace configurations.
3. Do not commit generated build output or ignored caches.

### 9. Verify the Rename

1. Search for stale application-identity references:

   ```sh
   rg -n 'apps/public|@dg/public|build:public|deploy:public|darcygraphix-public|publicAppOrigin|PUBLIC_ORIGIN|PublicRouterContext|backend,public,system' \
     --glob '!**/node_modules/**' \
     --glob '!**/dist/**' \
     --glob '!**/.output/**'
   ```

   The command should return no stale app-identity references. Investigate each result rather than performing a blind global replacement.

2. Confirm intended `public` uses remain:
   - `apps/storefront/public/` exists and contains the static assets.
   - `apps/storefront/vite.config.ts` still uses `publicDir: "public"`.
   - `/share/$token/{-$itemId}` and public Drive sharing names remain unchanged.
   - Convex public/internal terminology remains unchanged.
3. Build both affected frontend applications without running a dev server:

   ```sh
   pnpm build:storefront
   pnpm build:system
   ```

4. Do not run lint commands, `pnpm check`, test commands, or any dev server; repository instructions prohibit them for this task.
5. Inspect `git diff --stat` and `git diff --summary`. Confirm Git recognizes the app files as renames rather than deletions plus unrelated replacements where possible.
6. Inspect `git status --short` and ensure only the intended rename, naming updates, lockfile update, and documentation changes are present.

### 10. Perform the Production Cutover Separately

This step requires explicit approval immediately before deployment.

1. Deploy the renamed storefront Worker using `pnpm deploy:storefront`.
2. Confirm Cloudflare attached `darcygraphix.com` to `darcygraphix-storefront` and did not leave the custom domain routed to the old Worker.
3. Verify these production paths:
   - `/` loads the storefront.
   - `/order` loads the order flow.
   - `/showcase` and one service detail route load.
   - A valid `/share/<token>` link loads.
   - An invalid share token fails in the same way as before.
4. Deploy `workers/cfsystem-redirect` so its renamed `STOREFRONT_ORIGIN` binding takes effect.
5. Verify legacy URLs still redirect to the same destinations on `darcygraphix.com` or `system.darcygraphix.com`.
6. Check Worker logs for both Workers after the cutover.
7. Remove the old `darcygraphix-public` Worker only after the new Worker and domain are verified. Deleting the old Worker is a separate destructive production action and also requires explicit approval.

## Acceptance Criteria

- The customer-facing app lives at `apps/storefront` and is named `@dg/storefront`.
- Root commands and documentation consistently use `storefront`.
- App-specific symbols and redirect bindings use `storefront`, not `public`.
- The Cloudflare configuration names the Worker `darcygraphix-storefront`.
- `https://darcygraphix.com`, local port `3000`, and all existing routes behave unchanged.
- Static assets remain in `apps/storefront/public/`.
- Public Drive sharing and Convex public API terminology remain unchanged.
- The stale-reference search returns no old application identifiers.
- `pnpm build:storefront` and `pnpm build:system` complete successfully.
- No production deployment or old-Worker deletion occurs without explicit approval.
